# Soulforge UI 系统性重构评估与落地方案

- 项目：Soulforge（多 Agent 文档管理工作台）
- 日期：2026-08-12
- 状态：方案设计（待评审后实施）
- 背景：功能持续扩充（搜索/历史/同步/导入导出/跨Agent编辑/对比/新建Agent/lint/统计/审计/预设/LLM/AI整理/设置），单一面板承载压力过大。

---

## 一、现状盘点与功能分类

### 1.1 当前界面结构

- 布局：`TopBar`（12+ 个入口按钮）→ 三栏（`AgentTree`｜`FileTree`｜`EditorPane`）→ `StatusBar`
- 弹窗：14 种（`ModalState`）：search / history / diff / sync / import / template / stats / lint-all / audit / settings / cross-edit / preset / apply-preset / ai-cleanup
- 技术基线：React 18 + Vite + Monaco + Ant Design 风格自定义 CSS 变量，单文件 `App.tsx` 承载全部弹窗与状态

### 1.2 功能模块四大分类

> 频次为产品评估值（基于当前编辑工作流），人群默认「老板（单人多 Agent）」；交互复杂度按步骤数/状态数评级（低/中/高）。

#### A. 核心业务流程（高频 · 必须最流畅）

| 功能 | 当前入口 | 操作频次 | 使用人群 | 交互复杂度 |
|------|---------|---------|---------|-----------|
| Agent 选择/切换 | AgentTree 单击 | 高（每次会话多次） | 老板 | 低 |
| 文件浏览/打开 | FileTree 单击 | 高 | 老板 | 低 |
| 文档编辑 | EditorPane（Monaco） | 最高 | 老板 | 中 |
| 保存（Ctrl+S） | 编辑器工具栏 | 最高 | 老板 | 低 |
| 全局搜索（Ctrl+K） | TopBar | 高 | 老板 | 低 |
| 版本历史/回溯 | 编辑器工具栏 | 中 | 老板 | 中 |
| 应用预设 / AI 整理 | 编辑器工具栏 | 中 | 老板 | 中（向导+diff 确认） |

#### B. 高频操作功能（中高频 · 需入口可见但不抢占）

| 功能 | 当前入口 | 操作频次 | 使用人群 | 交互复杂度 |
|------|---------|---------|---------|-----------|
| 导出当前文件 | 编辑器工具栏 | 中 | 老板 | 低 |
| lint 检查（单文件/全量） | 编辑器工具栏 / TopBar | 中 | 老板 | 低 |
| 跨 Agent 编辑（Ctrl+Shift+E） | TopBar | 中 | 老板（多 Agent 场景） | 高 |
| 重新扫描 | TopBar | 中低 | 老板 | 低 |
| 对比 Diff | TopBar | 低中 | 老板 | 中 |

#### C. 低频配置管理（低频 · 应收敛、不占主视口）

| 功能 | 当前入口 | 操作频次 | 使用人群 | 交互复杂度 |
|------|---------|---------|---------|-----------|
| 设置（主题/显示分组） | TopBar → SettingsModal | 低 | 老板 | 低 |
| LLM Provider 管理 | 设置内弹窗 | 低 | 老板 | 中 |
| 预设管理（模板编辑/版本/回溯） | TopBar → PresetModal | 低 | 老板 | 高 |
| 新建 Agent（模板向导） | TopBar → TemplateModal | 低 | 老板 | 中 |
| 导入 | TopBar → ImportModal | 低 | 老板 | 中 |

#### D. 数据统计分析（低频 · 只读视角）

| 功能 | 当前入口 | 操作频次 | 使用人群 | 交互复杂度 |
|------|---------|---------|---------|-----------|
| 统计概览 | TopBar → StatsModal | 低 | 老板 | 低 |
| 审计日志 | TopBar → AuditModal | 低 | 老板 | 低 |
| lint 全量报告 | TopBar → GlobalLintModal | 低中 | 老板 | 中 |
| 状态栏指标（连接/文件数/警告数） | StatusBar 常驻 | 常驻低频 | 老板 | 低 |

### 1.3 当前痛点清单（重排校验需求之外的 UI 压力）

1. **顶栏信息过载**：一行 12+ 入口，低频配置（审计/统计/设置）与核心编辑操作同级并列，视觉无主次。
2. **操作路径冗长**：跨模块组合操作（如「对比 A/B → 修复 → 同步」）需多次开关弹窗，上下文不连续。
3. **核心功能不突出**：编辑/保存/搜索等高频动作没有视觉权重与快捷键引导，新用户无法快速识别主流程。
4. **弹窗堆叠导致上下文丢失**：14 种弹窗覆盖在编辑区上，弹窗内切换 Agent/文件后目标失效；刷新后弹窗状态全部丢失。
5. **无独立数据视角**：统计/审计/lint 报告挤在弹窗里，无法常驻观察与横向对比。
6. **响应式缺失**：`body { min-width: 1280px }`，窄屏/平板不可用，无法多端协作。
7. **扩展性差**：每新增一个功能 = 顶栏再添一个按钮 + 再开一种弹窗，压力持续累积。

## 二、两种界面架构对比评估

### 2.1 单一面板集成方案（现状）

**保留的优势**
- 零跳转：编辑上下文始终在同一视口，选中 Agent/文件全局唯一，操作连贯。
- 状态集中：`App.tsx` 单一状态源，跨功能共享（如 lint 结果 → 文件角标）实现简单。
- 短路径：搜索命中 → 直接打开文件，无需跨页返回。
- 改造成本低：在现有结构上收敛即可。

**承载压力（随功能增长的劣势）**
- 顶栏与弹窗数量线性膨胀，信息密度失控（现状 12+ 按钮、14 弹窗）。
- 高频与低频入口权重相同，核心工作流被稀释。
- 弹窗堆叠无导航栈，深路径（设置→LLM→测试）层级混乱。
- 无法自然容纳「常驻数据视角」与「多端适配」。

### 2.2 多页面拆分方案

**页面拆分逻辑（按用户操作路径，而非按功能穷举）**

| 页面 | 定位 | 承载模块（现状组件迁移） | 使用人群/频次 |
|------|------|------------------------|--------------|
| **主工作台 Workbench**（默认落地页） | 日常编辑工作流，保持三栏 + 编辑器 | AgentTree / FileTree / EditorPane / 搜索 / 历史 / 应用预设 / AI 整理 / lint 单文件 | 老板 · 最高频 |
| **业务功能页 Tools** | 跨 Agent 协同与批处理工具集 | 同步 / 跨Agent编辑 / 对比 Diff / 导入 / 导出全部 / 新建Agent（向导） | 老板 · 中频 |
| **系统配置页 Settings** | 全部配置与模板管理 | 设置（主题/显示分组）/ LLM Provider / 预设管理（模板编辑·版本·回溯） | 老板 · 低频 |
| **数据中心 Data** | 只读数据与合规视角 | 统计 / 审计 / lint 全量报告 / Agent 明细对比 | 老板 · 低频 |

**页面间跳转逻辑与数据传递规则**
- **全局上下文提升**：`selectedAgentId / selectedFile / dirty` 从 `App.tsx` 提升为顶层 Context（或轻量 store），四个页面共享——切换页面不丢失编辑上下文。
- **路由约定**（轻量 hash 路由，无需引入重路由库即可落地）：`#/workbench`、`#/tools`、`#/settings`、`#/data`；页面刷新后可还原。
- **跨页动作回跳**：Data/Tools 页「打开结果」（lint 定位、搜索命中、diff 定位）→ 记录目标 `{agentId, path, line}` → 跳转 Workbench 并 `openFile`；此为唯一跨页命令通道。
- **弹窗收敛原则**：仅 Workbench 保留「上下文相关弹窗」（历史/应用预设/AI 整理/搜索，全部依赖当前文件）；Tools/Settings/Data 全部为页面内嵌内容或页面级抽屉，**不再全局叠弹窗**。

**对比结论**

| 维度 | 单一面板（现状） | 多页面拆分（目标） |
|------|----------------|------------------|
| 信息密度 | 持续过载 | 按职责收敛，每页聚焦 |
| 核心流程突出度 | 低 | 高（Workbench 即默认页） |
| 操作连贯性 | 强（同视口） | 强（全局上下文不丢） |
| 配置/数据管理 | 弹窗叠层 | 独立页面，可常驻 |
| 多端适配 | 难（min-width 1280） | 每页独立响应式 |
| 扩展性 | 每功能+1按钮+1弹窗 | 按页/区块扩展，顶栏恒定 |
| 开发成本 | — | 中等（路由 + 状态提升 + 迁移） |

**推荐：采用多页面拆分方案，但以「收敛优先、渐进迁移」方式落地**（见第五节），保留单一面板操作连贯性优点。

## 三、全新 UI 落地方案

### 3.1 信息架构与导航

```
┌────────────────────────────────────────────────────────────┐
│ 侧边导航（64px 图标栏，可展开）  │  顶栏（每页独立、瘦身）   │
│  ● Workbench 工作台             │  [搜索] [扫描] [导出] 用户 │
│  ⇄ Tools      工具集            └───────────────────────────┘
│  ◇ Data       数据中心          页面内容区（响应式网格）      │
│  ⚙ Settings   系统配置                                        │
└──────────────────────────────────────────────────────────────┘
```
- **侧边导航固定 4 项**，替代现有顶栏 12+ 按钮的入口职责。
- **顶栏瘦身**：仅保留全局动作（搜索 Cmd+K、重新扫描、导出全部、连接状态），其余动作归属各页。
- **Workbench 三栏保留**，且三栏可独立折叠（现状已具备拖拽能力，扩展折叠记忆）。

### 3.2 响应式布局设计规范

| 断点 | 布局 | 处理策略 |
|------|------|---------|
| ≥1440px（桌面） | 三栏（导航/Agent+文件树合并可选项/编辑器） | 完整视口 |
| 1024–1439px | 两栏 | Agent 树折叠为图标列，文件树+编辑器 |
| 768–1023px（平板） | 单栏 + 抽屉 | 文件树/Agent 树为左侧抽屉，编辑器全宽 |
| <768px（手机/触屏） | 单栏全宽 | 编辑优先；导航沉底 Tab 栏（4 项）；Monaco 触屏只读+轻量编辑 |
- 所有弹窗在 <1024px 自动切换为**底部抽屉/全屏页**（统一 `ResponsivePanel` 组件）。
- 断点由 CSS 变量 + `useMediaQuery` 统一管理，不散落硬编码。

### 3.3 视觉设计系统（延续现有 token，补齐规范）

**色彩体系**（基于现有 `global.css` token 扩展）
- 主色 `--accent`（蓝）不变，新增 4 档色阶（50/500/600/700）用于状态与 hover。
- 语义色规范：`--success`（写操作成功）/ `--warning`（lint 警告）/ `--danger`（阻断）/ `--info`（信息）；使用场景白名单化（按钮禁用态、徽标、横幅、行内提示），禁止随意混用。
- 中性色阶：bg-base / bg-elevated / bg-hover / border / text-primary / text-secondary / text-tertiary（新增，用于说明文字）。
- 深/浅双主题 token 完全对齐（现有 `[data-theme='dark']` 已具备，补齐新增 token）。

**字体层级**
- 层级：`H1 20px/700` → 页面标题；`H2 15px/600` → 区块标题；`H3 13px/600` → 组标题；`body 14px/400`；`caption 12px`；`mono 12px`（路径/代码/ID）。
- 行高：正文 1.6，标题 1.3；字号统一用 CSS 变量（`--font-size-*`），不散落。

**组件规范**
- 按钮三级：`primary`（主操作，每区块≤1）/ `ghost`（次操作）/ `text`（行内弱操作）；尺寸 sm/md。
- 新增规范组件：`PageHeader`（标题+描述+主操作）、`DataCard`（数据视角）、`CommandPalette`（命令面板）、`Drawer`（响应式面板）、`EmptyState`（统一空态）、`Badge`（状态标签）。
- 间距 4px 网格；圆角 6px（控件）/8px（卡片）；阴影仅用于浮层，层级 ≤3。

### 3.4 核心操作交互流程优化

1. **命令面板 Cmd+K（替代分散入口）**
   - 可搜索：功能（含四个页面导航）、文件（现有搜索）、设置项。
   - 输入 `sync`/`审计`/`新建` 直接执行或跳页，大幅缩短路径；现有 Ctrl+K 语义平滑升级。
2. **保存反馈**：保存后编辑器标题栏徽标「已保存 · HH:mm:ss」+ 轻提示；可选「自动保存」（设置项，防抖 2s），彻底解决「保存按钮不亮/忘保存」类问题。
3. **应用预设 / AI 整理收敛为编辑器工具栏「整理 ▾」下拉**：两项均走既有「plan → diff 确认 → 执行」流程不变（复用现有 Apply*Modal 内部逻辑），仅入口归并。
4. **新建 Agent 向导**：模板选择 → 命名/工作区 → 创建结果（含文件清单）三步，从弹窗升级为页面级向导（Tools 页）。
5. **lint 工作流**：单文件行内提示（现有角标）保留；全量报告移至 Data 页，支持按 Agent/规则过滤、点击行定位回编辑。

### 3.5 信息层级优先级方案

| 优先级 | 层级 | 内容 | 视觉表达 |
|--------|------|------|---------|
| P0 | 编辑工作流 | Agent/文件/编辑器/保存/搜索 | 主视口三栏；快捷键；primary 按钮 |
| P1 | 业务动作 | 同步/对比/跨编辑/导入导出/新建 | Tools 页卡片化；顶栏不常驻 |
| P2 | 配置 | 设置/预设/LLM | Settings 页分组表单；仅图标入口 |
| P3 | 数据 | 统计/审计/lint 报告 | Data 页只读卡片；状态栏常驻摘要 |

- 视觉降噪原则：每页默认只显示 P0 主操作；P1–P3 通过导航/卡片进入，减少常驻元素。

### 3.6 方案解决的痛点 · 技术成本 · 学习成本

**痛点 → 方案对应**

| 痛点 | 方案手段 |
|------|---------|
| 顶栏信息过载 | 侧边 4 项导航 + 顶栏瘦身（3.1） |
| 核心功能不突出 | P0 视觉优先级 + 命令面板（3.5/3.4） |
| 弹窗堆叠上下文丢失 | 页面级内容 + 全局上下文提升 + 弹窗收敛（2.2） |
| 无数据视角 | Data 页常驻（2.2） |
| 多端不可用 | 响应式断点 + Drawer（3.2） |
| 扩展性差 | 按页/区块扩展，顶栏恒定（2.2） |

**落地技术成本预估**

| 工作项 | 内容 | 预估相对量级 |
|--------|------|------------|
| 路由与导航 | 轻量 hash 路由 + 侧边导航 + 页面骨架 | 小（无新依赖） |
| 状态提升 | `selectedAgentId/file/dirty` → Context；弹窗状态按页归位 | 中 |
| 组件抽离 | PageHeader / Drawer / DataCard / CommandPalette 新建 | 中 |
| 页面迁移 | 14 弹窗 → 4 页归类；Apply 流程复用 | 中 |
| 视觉系统 | token 补齐 + 字体层级 + 组件规范落库 | 中 |
| 响应式 | 断点 + 抽屉 + 触屏模式 | 中 |
| 命令面板 | 索引功能/文件/设置项 | 小 |
| 回归验证 | 全量 pytest + 前端 build + 冒烟 | 持续 |

> 综合量级：**中**。风险主要在弹窗→页面迁移与全局状态提升，建议按第五节分阶段推进，每阶段可独立上线回滚。

**用户学习成本控制**
- 快捷键全部保留并扩充（Cmd+K 命令面板是唯一新增心智负担，且天然降低学习成本——可搜索一切）。
- 页面命名与现有弹窗标题一一对应（统计→Data、设置→Settings），用户无需重新记忆。
- 渐进迁移：第一版仅收敛顶栏与命令面板，界面主体不变；路由/导航分阶段启用。
- 内置「首次使用引导」：对新用户高亮 Cmd+K 与保存快捷键，2 步内完成。

## 四、实施路线（分阶段，每阶段可独立验收）

| 阶段 | 内容 | 验收标准 |
|------|------|---------|
| P1 收敛（低风险） | 命令面板 Cmd+K；顶栏按钮按四类分组收纳（分组下拉/图标折叠） | 顶栏入口 ≤6；现有功能零回归 |
| P2 骨架（中风险） | hash 路由 + 侧边导航；Settings/Data 两页从弹窗迁出；全局上下文提升 | 配置/数据常驻页面；编辑上下文跨页不丢 |
| P3 迁移（中风险） | Tools 页（同步/对比/跨编辑/导入导出/新建）迁出；Workbench 弹窗收敛为 3 种内 | Workbench 仅保留文件上下文相关弹窗 |
| P4 视觉与响应式 | token/字体/组件规范落库；断点 + Drawer + 触屏模式 | 1280px 以下可用；深浅主题一致 |
| P5 打磨 | 自动保存、首次引导、数据页交互增强 | 全量回归 + 冒烟通过 |

## 五、风险与回滚

- **弹窗 → 页面迁移**：每个弹窗组件逻辑不动，仅宿主从 `App.tsx` 移到页面容器，回滚=恢复宿主，风险可控。
- **全局状态提升**：用 Context 包裹现有 `App` 内部状态，迁移期间保持双写兼容，最后统一收敛。
- **视觉改动**：token 向后兼容（旧 token 保留为别名），深色模式同步验收。
- 全量回归基线：后端 129 passed / 1 skipped；前端 `tsc --noEmit && vite build` 通过。
